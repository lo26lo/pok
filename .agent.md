## 📂 Structure du Projet

### ✅ Répertoires Actifs (À UTILISER)

- **`core/`** : Modules Python principaux (augmentation, mosaïques, holographiques, etc.)
- **`scripts/`** : Scripts utilitaires et outils de gestion
- **`tests/`** : Tests unitaires et d'intégrité
- **`docs/`** : Documentation complète du projet
- **`config/`** : Fichiers de configuration (requirements, api_config)
- **`models/`** : Modèles YOLO et mappings de cartes
- **`images/`** : Images sources des cartes Pokémon
- **`output/`** : Résultats générés (augmentations, mosaïques, datasets)
- **`backgrounds/`** : Images de fond pour mosaïques
- **Racine** : `GUI_v3.1_modern.py`, `START.bat`, `INSTALL.bat`, `README.md`

### ❌ Répertoires à IGNORER

- **`obsolete/`** : Fichiers obsolètes conservés pour référence historique uniquement
  - ⚠️ **NE JAMAIS** utiliser le code de ce répertoire
  - ⚠️ **NE JAMAIS** suggérer d'utiliser ces fichiers
  - ⚠️ Ces fichiers sont remplacés par des versions plus récentes dans les répertoires actifs

## 🎯 Règles de Base

### 1. Racine Propre

La racine doit rester **propre** avec uniquement :
- ✅ `START.bat` - Lanceur principal
- ✅ `INSTALL.bat` - Installation
- ✅ `README.md` - Documentation quick-start
- ✅ `GUI_v3.1_modern.py` - Interface graphique
- ✅ `.gitignore` - Configuration Git
- ✅ `.agent.md` - Instructions pour agents IA (ce fichier)
- ❌ **AUCUN** autre fichier `.py`, `.bat`, `.md`, `.json`, `.txt`

### 2. Organisation des Nouveaux Fichiers

**Avant de créer un fichier, déterminer son emplacement** :
- **Script Python** → `scripts/`
- **Test** → `tests/`
- **Documentation** → `docs/`
- **Configuration** → `config/`
- **Module core** → `core/`

### 3. Versions Optimisées (GPU)

**TOUJOURS utiliser les versions optimisées** :
- ✅ `core/mosaic_optimized.py` (pas `mosaic.py`)
- ✅ `core/holographic_augmenter_optimized.py` (pas `holographic_augmenter.py`)
- ✅ `core/auto_balancer_optimized.py` (pas `auto_balancer.py`)

Les versions optimisées incluent :
- Support GPU automatique (CUDA/PyTorch)
- Vectorisation NumPy
- Multi-threading
- Fallback CPU si GPU indisponible

### 4. Migration Excel → YAML (TERMINÉE)

- ✅ Base de données : `models/cards_database.yaml`
- ❌ **NE PLUS** utiliser Excel (`card_database.xlsx`)
- ❌ **NE PLUS** référencer `load_prices_from_excel()`
- ✅ Utiliser `load_prices()` de `core/utils.py`

## 🔧 Environnement Technique

### Python
- **Version recommandée** : 3.12
- **Versions supportées** : 3.10, 3.11, 3.12
- **Versions interdites** : 3.13+ (incompatibilité NumPy 1.x)

### Dépendances Critiques
- **NumPy** : `< 2.0` (OBLIGATOIRE pour imgaug)
- **OpenCV** : `< 4.10.0` (compatibilité NumPy 1.x)
- **imgaug** : `>= 0.4.0` (nécessite NumPy < 2.0)
- **PyTorch** : Avec CUDA pour GPU (auto-détecté)

### Environnement Virtuel
- **TOUJOURS** utiliser `.venv/` pour les tests/scripts
- **JAMAIS** exécuter hors du venv
- Utiliser `scripts\run_test.bat` ou `scripts\run_script.bat`

## ✅ Workflow de Modification

1. **Planifier** : Créer `.planning/YYYY-MM-DD_description.md` pour modifications majeures
2. **Proposer** : Expliquer les changements avant de les faire
3. **Vérifier** : S'assurer de l'emplacement correct des fichiers
4. **Documenter** : Mettre à jour `README.md` et/ou `docs/README_COMPLET.md`
5. **Tester** : Exécuter dans `.venv/`
6. **Committer** : Message clair suivant convention (feat/fix/perf/docs/refactor)
