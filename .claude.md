## ⚠️ RÈGLE ABSOLUE #1 : Documentation obligatoire

**TOUJOURS mettre à jour la documentation après CHAQUE modification de fonctionnalité !**

### Checklist documentation (à suivre SYSTÉMATIQUEMENT) :

#### 1. **README.md** (racine)
Mettre à jour si :
- ✅ Changement visible par l'utilisateur
- ✅ Nouvelle fonctionnalité
- ✅ Modification de workflow
- ✅ Changement de commandes/scripts

#### 2. **docs/README_COMPLET.md**
Mettre à jour si :
- ✅ Modification technique
- ✅ Changement d'architecture
- ✅ Ajout/suppression de dépendances
- ✅ Modification de configuration

#### 3. **docs/CHANGELOG.md**
**TOUJOURS** mettre à jour pour :
- ✅ Toute modification de fonctionnalité
- ✅ Correction de bug
- ✅ Amélioration de performance
- ✅ Ajout/modification de feature

Format : `[Version] - Date - Description`

#### 4. **Docs spécifiques**
Selon le type de changement :
- `docs/HELP.md` : Si impact sur l'utilisation
- `docs/FEATURES.md` : Si nouvelle feature ou modification
- `docs/DEPENDENCIES_MAP.md` : Si changement de dépendances
- `scripts/SCRIPTS_REFERENCE.py` : Si ajout/modif script/test

## 📋 Workflow Standard

### Avant tout commit :

```
1. Faire les modifications de code
2. ⚠️ STOP - Vérifier la checklist documentation
3. Mettre à jour tous les fichiers doc concernés
4. Commit CODE + DOCUMENTATION ensemble
5. Push sur GitHub
```

### Exemple de commit correct :

```bash
# ❌ MAUVAIS (code seul)
git commit -m "feat: add folder buttons"

# ✅ BON (code + doc dans 2 commits séparés)
git commit -m "feat(gui): add folder buttons to 4 views"
git commit -m "docs: update README and CHANGELOG for folder buttons"
```

## 💬 Messages de Commit

### Format obligatoire
```

```

### Types autorisés
- **feat** : Nouvelle fonctionnalité
- **fix** : Correction de bug
- **docs** : Documentation uniquement
- **perf** : Amélioration de performance
- **refactor** : Refactorisation
- **test** : Ajout/modification de tests
- **chore** : Maintenance

```bash
✅ feat(gui): add folder open buttons to 4 main views
✅ perf(core): optimize mosaic generation with ProcessPoolExecutor
✅ docs: update README and CHANGELOG for v3.2.1
✅ fix(core): handle corrupted images gracefully
```

## 🔄 Workflows Types

### Workflow 1 : Nouvelle fonctionnalité GUI
```
1. Modifier GUI_v3.1_modern.py
2. Tester : START.bat
3. ⚠️ DOCUMENTER :
   - README.md (section Features)
   - docs/README_COMPLET.md (section GUI)
   - docs/FEATURES.md
   - docs/CHANGELOG.md
4. Commit : feat(gui): <description>
5. Commit doc : docs: update for <feature>
```

### Workflow 2 : Nouveau script
```
1. Créer scripts/mon_script.py
2. Mettre à jour scripts/SCRIPTS_REFERENCE.py
3. Tester : scripts\run_script.bat mon_script
4. ⚠️ DOCUMENTER :
   - docs/README_COMPLET.md (section Scripts)
   - docs/CHANGELOG.md
5. Commit ensemble : script + SCRIPTS_REFERENCE.py + docs
```

### Workflow 3 : Optimisation performance
```
1. Modifier le code (ex: core/mosaic_optimized.py)
2. Mesurer le gain de performance
3. ⚠️ DOCUMENTER :
   - README.md (mettre à jour les chiffres de perf)
   - docs/README_COMPLET.md (expliquer l'optimisation)
   - docs/CHANGELOG.md (ajouter en section Performance)
4. Commit : perf(core): <description avec gain>
5. Commit doc : docs: update performance metrics
```

## 🚨 Erreurs Fréquentes à Éviter

### ❌ Oubli de documentation
```bash
# MAUVAIS
git add core/mosaic_optimized.py
git commit -m "feat: optimize mosaics"
git push

# BON
git add core/mosaic_optimized.py
git commit -m "feat(core): optimize mosaic generation (30-60x faster)"
# ⚠️ PUIS mettre à jour docs
git add README.md docs/README_COMPLET.md docs/CHANGELOG.md
git commit -m "docs: update for mosaic optimizations"
git push
```

### ❌ Fichiers à la racine
```bash
# MAUVAIS
touch new_script.py          # À la racine !
touch NOTES.md              # À la racine !

# BON
touch scripts/new_script.py  # Dans scripts/
touch docs/NOTES.md         # Dans docs/
```

### ❌ Tests hors venv
```bash
# MAUVAIS
python tests/test_nom.py     # Mauvais environnement

# BON
scripts\run_test.bat test_nom
```
